# FQDN in Kubernetes

## What is an FQDN?
A **Fully Qualified Domain Name** is the complete, unambiguous name of a host, written from the most specific label to the root: `host.subdomain.domain.tld.` (the trailing dot is the DNS root and is usually left out).

- `backend` – a short name; only means something if the resolver knows which domain to append.
- `backend.default.svc.cluster.local` – an FQDN; resolves the same way from any Pod in any namespace.

In Kubernetes the "domain" is the cluster domain, `cluster.local` by default (`kubelet --cluster-domain`).

## Kubernetes Service DNS
Every Service gets an A/AAAA record from CoreDNS the moment it is created:

```text
<service-name>.<namespace>.svc.<cluster-domain>
```

- ClusterIP Service → the record points at the virtual ClusterIP.
- Headless Service (`clusterIP: None`) → the record returns the Pod IPs directly (one A record per Ready Pod).
- ExternalName Service → a CNAME to the external hostname, no IP.
- Named ports also get SRV records: `_http._tcp.backend.default.svc.cluster.local`.

## Kubernetes DNS naming convention

| Object | Record | Example |
|---|---|---|
| Service | `svc.ns.svc.cluster.local` | `yatri-backend-service.default.svc.cluster.local` |
| Pod (by IP) | `10-244-0-17.ns.pod.cluster.local` | `10-244-0-17.default.pod.cluster.local` |
| StatefulSet Pod via headless Service | `pod.svc.ns.svc.cluster.local` | `db-0.db.default.svc.cluster.local` |
| Service SRV | `_port._proto.svc.ns.svc.cluster.local` | `_http._tcp.yatri-backend-service.default.svc.cluster.local` |

Reading an FQDN right to left: `cluster.local` (cluster) → `svc` (it is a Service) → `default` (namespace) → `yatri-backend-service` (name).

## Namespace-based DNS
Namespaces are the second label, so the same Service name can exist in several namespaces without clashing:

```text
api.dev.svc.cluster.local
api.staging.svc.cluster.local
api.prod.svc.cluster.local
```

Inside a Pod, `/etc/resolv.conf` is generated by the kubelet:

```text
nameserver 10.96.0.10                       # kube-dns Service -> CoreDNS
search default.svc.cluster.local svc.cluster.local cluster.local
options ndots:5
```

The `search` list is what makes short names work:

| From a Pod in `default`, you type | Resolver actually tries | Works? |
|---|---|---|
| `api` | `api.default.svc.cluster.local` | only if `api` is in `default` |
| `api.prod` | `api.prod.svc.cluster.local` | yes – cross-namespace short form |
| `api.prod.svc.cluster.local` | exactly that | always |

`ndots:5` means any name with fewer than 5 dots is first tried with every search suffix before being sent out as-is. That is why `google.com` from a Pod produces 3 useless cluster lookups before the real one, and why using the full FQDN (or a trailing dot) in configs is faster.

## Pod-to-Service communication
```text
frontend Pod (ns: default)
   │  GET http://yatri-backend-service/api
   ▼
/etc/resolv.conf  →  nameserver 10.96.0.10, search default.svc.cluster.local …
   ▼
CoreDNS  →  yatri-backend-service.default.svc.cluster.local = 10.108.21.5
   ▼
ClusterIP 10.108.21.5:80  (kube-proxy iptables DNAT)
   ▼
one Ready backend Pod, e.g. 10.244.0.23:5000
```

Pods never need to know Pod IPs. They talk to the Service name; DNS turns it into the ClusterIP; kube-proxy turns the ClusterIP into a Pod IP. If a Pod is replaced, only the last hop changes.

## Examples of Kubernetes FQDNs
From this session's manifests on minikube:

```text
kubernetes.default.svc.cluster.local                       # the API server Service
kube-dns.kube-system.svc.cluster.local                     # CoreDNS itself
web-service-clusterip.default.svc.cluster.local            # 01-clusterip (ClusterIP 10.111.237.96 on my cluster)
nodeport-web-service.default.svc.cluster.local             # 02-nodeport
external-api.default.svc.cluster.local  -> CNAME api.github.com   # 04-externalname
yatri-db-0.yatri-db-headless.default.svc.cluster.local      # 05-headless StatefulSet Pod
```

Quick test from inside the cluster (used in the Submission screenshots):

```bash
kubectl run dns-test --rm -it --image=busybox:1.36 --restart=Never -- \
  nslookup web-service-clusterip.default.svc.cluster.local
```

The answer comes from `10.96.0.10` (the kube-dns Service) and returns the ClusterIP of the Service.
